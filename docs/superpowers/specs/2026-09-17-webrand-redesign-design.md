# Редизайн WeBrand: публичный сайт + админ-панель

Дата: 2026-09-17 · Статус: ждёт «начинай» от владельца

## 1. Цель

Полностью обновить облик всей системы — от лендинга до админки. Сайт должен стать
живым, динамичным и современным: для агентства, которое продаёт дизайн, собственный
сайт — главный кейс. Функционал, данные, SEO и контракты с бэкендом при этом не ломаем.

Текущее состояние (аудит 2026-09-17): аккуратный, но шаблонный «корпоративный
минимализм» — белый фон, синие акценты, скруглённые карточки, fade-up при скролле.
База UI UX Pro Max для типов «Creative Agency» / «Marketing Agency» называет это
антипаттерном («Corporate minimalism + Hidden portfolio») и рекомендует
Motion-Driven подачу, крупную типографику и Storytelling-структуру.

Масштаб: ~5 000 строк UI на сайте (Next.js 15, 13 маршрутов, 21 компонент) и
~6 200 строк в админке (Vite + React 18, 8 экранов, 5 форм-дроверов, light/dark).

## 2. Решения владельца (зафиксированы 2026-09-17)

| Вопрос | Решение |
|---|---|
| Визуальное направление | **Bold Kinetic** — светлая основа, гигантская типографика, бегущие строки, тёмные секции для ритма |
| Палитра | Фирменный синий `#2B5ED3` + **один яркий акцент** |
| Эффекты | **Максимум** — 3D, кастомный курсор, сложная хореография скролла |
| Контент | Текущие тексты и секции + **новые секции без выдуманных фактов** |
| Админка | Новый визуал всех экранов + **новая главная-дашборд** |
| 21st.dev | Бесплатный тариф: каталог как ориентир, **2 извлечения кода в день** — на самое сложное |
| Портфолио | Владелец **пришлёт скриншоты работ** (обложки кейсов) |
| Процесс | **Сначала концепт главной → «ок» владельца → всё остальное** |

## 3. Подход к реализации

Рассмотрены три варианта:

- **A. Редизайн на месте в долгоживущей ветке `redesign`** *(выбран)*. Меняем слой
  представления внутри существующих приложений; маршруты, `lib/api.ts`, SEO, логика
  форм остаются. Vercel сам собирает preview-ссылки для ветки. Прод не трогаем до
  явного «мержи».
- B. Параллельное приложение `frontend-v2/` с нуля. Чище старт, но дублирует слой
  данных и SEO, требует перенастройки Vercel, выше риск регрессий в формах.
- C. Посекционные правки прямо в `main`. Посетители увидят полустарый-полуновый сайт.

## 4. Дизайн-система (общая для сайта и админки)

### 4.1 Основа
- Tailwind остаётся **v3.4** в обоих приложениях (переезд на v4 — риск без визуальной
  отдачи).
- Переходим на **конвенции shadcn/ui**: семантические токены через CSS-переменные,
  утилита `cn()`, папка `components/ui/`. Компоненты 21st.dev — это shadcn-реестр,
  так что любой извлечённый компонент встаёт без переделки.
- Все новые компоненты — маленькие, с одной ответственностью. Файлы-монстры
  (`ContactForm.tsx`, 1 116 строк) при редизайне делим на шаги/поля, **не меняя логику**.

### 4.2 Цвет
- `brand.50–900` без изменений, `brand-600 = #2B5ED3` — цвет логотипа.
- Нейтрали: «чернила» `ink` (почти чёрный с холодным подтоном) для текста и тёмных
  секций; «бумага» `paper` (тёплый off-white) для светлых. Чистый `#000`/`#FFF` — только
  в точечных контрастах.
- **Акцент: электрик-лайм** (ориентир `#C8F135`). Используется как маркер: подложка под
  словами, бейджи, курсор, hover-заливки — всегда с тёмным текстом поверх (на белом
  лайм как цвет текста не проходит контраст). Это **мой выбор, а не совпадение из базы
  палитр** — в базе для агентств только розово-циановые схемы, под синий бренд не
  подходят. В концепте покажу и оранжевую альтернативу; замена — один токен.
- Все пары текст/фон — контраст ≥ 4.5:1 (WCAG AA).

### 4.3 Типографика (обязательна кириллица)
- **Заголовки: Unbounded** (вариативный, 200–900, кириллица есть) — широкий
  геометрический гротеск, рифмуется с логотипом.
- **Текст: Manrope** — остаётся, уже подключён, преемственность бренда.
- **Метки и цифры: JetBrains Mono** — «01 / УСЛУГИ», теги, счётчики.
- Всё через `next/font` (самохостинг, без сдвигов макета). Размеры заголовков — через
  `clamp()`: длинные русские слова («ПРЕВРАЩАЕМ») обязаны помещаться на 360 px.

### 4.4 Движение
- **GSAP + ScrollTrigger + SplitText** (все плагины GSAP теперь бесплатны) — хореография
  скролла, пины, разбиение текста. **Lenis** — плавный скролл. **Framer Motion** остаётся
  для компонентного уровня (модалки, presence, layout).
- Токены: вход `expo.out` / `cubic-bezier(0.16,1,0.3,1)`; микровзаимодействия 150–300 мс;
  сюжетные сцены 600–1000 мс; выход быстрее входа.
- `prefers-reduced-motion` — всё вырождается в простые проявления без движения.

## 5. Публичный сайт

### 5.1 Главная (Storytelling-Driven)
1. **Hero** — кинетический заголовок (SplitText-проявление по строкам, сменяющееся
   слово), 3D-объект в фирменном синем, реагирующий на курсор; кликабельные чипы услуг
   (фича от 2026-08 сохраняется, якоря `service-N` остаются); CTA; строка доверия
   «30+ компаний».
2. **Тикер услуг** — бегущая строка, скорость реагирует на скорость скролла.
3. **О компании** — манифест, слова «загораются» по мере скролла + 4 ценности в бенто.
4. **Услуги** — липкие карточки-стопка; подуслуги и `ServiceDetailModal` сохраняются.
5. **Процесс** — тёмная секция, горизонтальный пин-скролл из 4 шагов (на мобильном —
   обычная вертикальная лента).
6. **Портфолио** — крупные кейсы с обложками; фильтры-маршруты (`/devprojects` и др.)
   сохраняются; курсор «Смотреть». У проектов без обложки — **постер из логотипа и
   акцентного цвета проекта** (поле `accent` есть у каждого), так что раздел выглядит
   цельно при любом наполнении.
7. **Партнёры** — двухрядная лента логотипов.
8. **FAQ** — новая секция, черновик текстов пишу я, владелец правит.
9. **CTA** — гигантское «Готовы вырасти?», магнитная кнопка, контакты.
10. **Футер** — огромный вордмарк, навигация, соцсети (обработчик Telegram из
    `lib/telegram.ts` сохраняется), ссылка «Блог» (требование SEO).

Блок цифр: на сайте сейчас есть единственное числовое заявление — «30+ компаний».
Делаю блок, только если владелец даст 2–3 реальные цифры. Отзывы не выдумываю.

### 5.2 Внутренние страницы
`/portfolio/[slug]` (кейс: обложка, мета, описание, «следующий кейс»), `/smm`
(рилсы, партнёры, SMM-проекты), `/vacancies` (список + отклик с PDF), `/news` и
`/news/[slug]` (светлая редакционная вёрстка — читаемость важнее эффектов), `/brief`,
`404`, `ContactModal` + квиз `ContactForm`, `BriefForm`. Переходы между страницами —
шторка.

### 5.3 «Максимум» без потери мобильной аудитории
Тяжёлое включается **только на способных устройствах** и **после первой отрисовки**:

| Эффект | Десктоп | Мобильный / слабое устройство / reduced-motion |
|---|---|---|
| 3D-сцена (three.js, ленивая загрузка) | да | статичный градиентный объект |
| Кастомный курсор | да (fine pointer) | нет |
| Пин-скролл, горизонтальные сцены | да | вертикальная лента |
| SplitText, маркизы, параллакс | да | упрощённые / выключены при reduced-motion |
| Короткая интро-заставка (≤ 1 с, раз за сессию) | да | да, CSS-only |

Видеофоны: своих видео у агентства сейчас нет (0 рилсов в базе). Слот под шоурил
закладываю; появится видео — встанет без переделки.

## 6. Админ-панель

- **Кит компонентов** переводится на общие токены и shadcn-конвенции: кнопки, поля,
  таблицы, дроверы, тосты, диалоги, скелетоны, пустые состояния. Плотность — компактная.
  Обе темы сохраняются.
- **Экраны**: вход, вакансии, отклики, проекты, рилсы, партнёры, новости, заявки
  (+ деталь заявки), все формы-дроверы. Функционал один в один: drag-and-drop порядок,
  фильтры, поиск, публикация, загрузка файлов.
- **Новая главная-дашборд** (`/`, сейчас редирект на `/vacancies`): KPI-карточки (заявки
  и отклики за сегодня / 7 дней, опубликованные вакансии/проекты/новости), график
  заявок по дням за 30 дней, последние заявки, быстрые действия. Данные считаются на
  клиенте из существующих эндпоинтов (`/api/leads/journal/` отдаёт полный список с
  `created_at`) — **бэкенд не меняется**. График — собственный лёгкий SVG, без тяжёлых
  чарт-библиотек; перед реализацией сверяюсь со скиллом `dataviz`.
- Движение в админке сдержанное (150–250 мс): это рабочий инструмент, не витрина.
- Заодно чиню найденное: `validateDOMNesting` (`<div>` внутри `<table>`) на вакансиях.

## 7. Что НЕ меняется

- API, модели, миграции, авторизация, троттлинг, honeypot, Telegram-доставка.
- Контракты из `CLAUDE.md`: `slug` вакансии ↔ `id`; id направлений квиза
  (`smm/design/dev/ads/unsure`) ↔ `KNOWN_SELECTED`; словари иконок/акцентов/категорий;
  enum опыта и границы возраста; порядок только через drag-and-drop.
- SEO: metadata, canonical, JSON-LD, sitemap, robots, семантика `<article>`/один `<h1>`,
  отсутствие «Блога» в шапке.
- Валидация и сценарии форм (квиз, отклик с PDF, бриф) — меняется только внешний вид.

## 8. Бюджеты качества

- Lighthouse, главная: Performance ≥ 85 (мобильный) / ≥ 90 (десктоп), Accessibility ≥ 95,
  SEO = 100. CLS < 0.1. 3D и GSAP-плагины не попадают в критический путь.
- Клавиатурная навигация и видимый фокус везде; тач-цели ≥ 44 px; alt у изображений.
- Брейкпоинты проверки: 375, 768, 1024, 1440.

## 9. Тестирование (как реальный пользователь)

- `npm run build` в обоих приложениях — единственный формальный гейт проекта.
- Playwright, три ширины: все маршруты без ошибок консоли; якоря шапки; чипы hero
  (существующий набор тестов); полный квиз → заявка сохраняется → видна в журнале
  админки; отклик на вакансию с PDF; бриф; фильтры портфолио и страницы кейсов;
  блог: список, пагинация, статья; админка: вход, CRUD каждого ресурса, drag-сортировка,
  переключение темы, цифры дашборда против API.
- Отдельные прогоны: `prefers-reduced-motion`, только клавиатура, мобильный профиль.
- Для локальной проверки форм добавляю `http://localhost:3000` в `CORS_ALLOWED_ORIGINS`
  локального `backend/.env` (сейчас его там нет — браузерные POST с 3000 блокируются).

## 10. Этапы и контрольные точки

| Этап | Содержание | Контрольная точка |
|---|---|---|
| 0 | Ветка `redesign`, токены, шрифты, motion-инфраструктура, **концепт главной**: hero + тикер + услуги + портфолио | preview-ссылка + скриншоты → **«ок» владельца** |
| 1 | Остальные секции главной, шапка, футер, интро, курсор, переходы | preview |
| 2 | Внутренние страницы, формы, модалки, 404 | preview |
| 3 | Админка: кит → каркас → таблицы → формы → вход → дашборд | preview |
| 4 | Сквозное тестирование, Lighthouse, правки, обновление устаревшего `CLAUDE.md` | отчёт → «мержи» |

Каждый этап заканчивается сборкой, браузерным прогоном и честным отчётом: что
проверено, что нет, что сломалось.

## 11. Что нужно от владельца

1. **Обложки кейсов.** Лучший канал — прод-админка: Проекты → карандаш → «Обложка».
   Тогда картинки сразу попадают в API и на сайт. Ориентир: 1600×1000 (16:10), JPG/WebP,
   до ~400 КБ. Для SMM-проектов подойдёт скриншот ленты или коллаж. Старт это **не
   блокирует**: постер-фолбэк нужен в любом случае (обложки будут не у всех), а
   загруженные обложки подхватятся автоматически.
2. 2–3 реальные цифры для блока статистики (лет на рынке, проектов, человек в
   команде) — либо решение блок не делать.
3. Правки к черновику FAQ, когда он появится.
4. Позже: добавить preview-домен ветки в `CORS_ALLOWED_ORIGINS` на Railway, если
   захочется проверять отправку форм прямо на preview-ссылке.
